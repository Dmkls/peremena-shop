# Перемена – интернет-магазин учебных товаров

Проект выполнен в рамках летней практики.
Цель работы – разработать веб-приложение интернет-магазина, в котором покупатель может просматривать
каталог, добавлять товары в корзину и оформлять заказы, а администратор – управлять ассортиментом
и обрабатывать заказы.

Используемые технологии: Python 3.11+, Django 5.2, SQLite, шаблоны Django, CSS и JavaScript без
сторонних библиотек. Выбор Django обусловлен тем, что в нём уже есть ORM, система миграций,
аутентификация, защита от CSRF и административная панель, поэтому основное время можно уделить
логике самого магазина. SQLite не требует отдельного сервера и подходит для учебного проекта.

## Запуск

```bash
# создание и активация виртуального окружения
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

# установка зависимостей
pip install -r requirements.txt

# создание базы данных
python manage.py migrate

# заполнение демонстрационными данными (6 категорий, 21 товар, 2 пользователя)
python manage.py seed --with-users

# запуск сервера
python manage.py runserver
```

После запуска сайт доступен по адресу http://127.0.0.1:8000/.

Для проверки команда `seed --with-users` создаёт два аккаунта:

| Логин   | Пароль       | Роль          |
|---------|--------------|---------------|
| `admin` | `admin12345` | администратор |
| `buyer` | `buyer12345` | покупатель    |

Собственного администратора можно создать командой `python manage.py createsuperuser`.

Запуск тестов: `python manage.py test`.

## Функциональность

В системе предусмотрены три роли пользователей.

**Гость** может просматривать главную страницу, каталог и карточки товаров, искать товары по названию
и описанию, фильтровать их по категории, цене и наличию, сортировать, а также зарегистрироваться
или войти в систему.

**Покупатель** дополнительно может добавлять товары в корзину, изменять количество и удалять позиции,
оформлять заказ с указанием ФИО, телефона, адреса и комментария, а также просматривать свои заказы
и их статусы.

**Администратор** работает в разделе «Управление» (`/manage/`). На главной странице раздела выводятся
новые заказы и товары, которые заканчиваются на складе. Администратор может добавлять, изменять
и удалять товары (с загрузкой изображения) и категории, просматривать заказы с фильтром по статусу
и менять статус заказа. Дополнительно доступна стандартная административная панель Django (`/admin/`).

Заказ проходит статусы: «новый», «собирается на складе», «передан службе доставки», «доставлен».
Заказ также может быть отменён.

## База данных

Структура базы данных создаётся миграциями Django. Основные сущности приведены в таблице.

| Сущность        | Модель             | Основные поля |
|-----------------|--------------------|---------------|
| Пользователь    | `accounts.User`    | username, email, хеш пароля, is_staff |
| Категория       | `catalog.Category` | name, slug, description |
| Товар           | `catalog.Product`  | category, name, description, price, stock, image, is_active |
| Позиция корзины | `orders.CartItem`  | user, product, quantity |
| Заказ           | `orders.Order`     | user, status, full_name, phone, address, comment, created_at |
| Позиция заказа  | `orders.OrderItem` | order, product, product_name, price, quantity |

В позиции заказа название и цена товара сохраняются на момент покупки. Благодаря этому состав
и сумма заказа не меняются, если товар позже подорожает или будет удалён из каталога.

## Безопасность

При разработке были учтены основные требования к безопасности веб-приложений:

- корзина, оформление заказа и список заказов доступны только авторизованным пользователям;
- раздел `/manage/` доступен только администраторам: гость перенаправляется на страницу входа,
  покупатель получает ошибку 403;
- пользователь видит только свою корзину и свои заказы, при попытке открыть чужой заказ возвращается 404;
- пароли хранятся в виде хеша (PBKDF2), при регистрации проверяется сложность пароля;
- все действия, изменяющие данные, выполняются POST-запросами с CSRF-токеном;
- шаблоны Django экранируют выводимые данные (защита от XSS), а ORM формирует параметризованные
  запросы (защита от SQL-инъекций);
- адрес перенаправления после добавления товара в корзину проверяется, поэтому перейти на сторонний
  сайт через параметр `next` нельзя;
- оформление заказа выполняется в транзакции с блокировкой остатков, что исключает продажу большего
  количества товара, чем есть на складе;
- `SECRET_KEY`, `DEBUG` и `ALLOWED_HOSTS` задаются через переменные окружения `DJANGO_SECRET_KEY`,
  `DJANGO_DEBUG` и `DJANGO_ALLOWED_HOSTS`, значения по умолчанию предназначены только для разработки.

## Структура проекта

```
config/        настройки проекта и корневые маршруты
accounts/      модель пользователя, регистрация, вход и выход
catalog/       категории и товары, главная страница, каталог, команда seed
orders/        корзина, оформление заказа, заказы покупателя
dashboard/     раздел администратора /manage/
templates/     HTML-шаблоны
static/        стили, скрипты и изображения
designs.html   варианты оформления, из которых выбирался дизайн сайта
```
